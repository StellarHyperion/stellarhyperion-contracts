# Protocol Security Assumptions

Hyperion is a cross-chain router, not a consensus bridge. Every inbound token credit depends on an external rail authenticator whose cryptographic or host-level check runs before `HyperionRouter` accepts delivery, and every privileged configuration surface falls into an explicit authority regime that separates timelocked router expansions from immediate risk-narrowing brakes and direct adapter administration.

This document is executable documentation. Both `@hyperion/protocol` (`verifySecurityAssumptions`) and the `hyperion-router` Soroban test suite (`test::security_assumptions`) parse the matrices below and cross-check every referenced file path, entrypoint signature, in-body authorization guard, representative test assertion, and contract-wide trust surface. Adding a new privileged setter or inbound receiver call without registering it here, or breaking any referenced symbol, fails automated verification.

## Active Deployment Scope and Gating

- **Active deployment:** Stellar Testnet outbound `AxelarIts` and `Cctp` (`ACTIVE_TESTNET_RAILS = ["Cctp", "AxelarIts"]`).
- **Explicitly gated surfaces:** Stellar inbound router receivers, `AxelarGmp`, `Allbridge`, and the EVM `HyperionRouter` / `CctpAdapter` / `AxelarItsAdapter` contracts remain gated until independently validated.
- **Preserved invariants:** Exact integer amounts (no floating-point conversion), authenticated rail dispatch (`caller == cfg.router` / `msg.sender == ROUTER`), route-scoped 32-byte replay protection, and recipient-bound parked claims (`PendingClaim`) are preserved unchanged across all checks.

## Inbound Evidence Authentication Matrix

Each rail states which external provider authenticates inbound evidence before funds can reach a recipient or park as a `PendingClaim`. On the active Stellar Testnet outbound `AxelarIts` bare shape, inbound bare transfers are delivered directly by Axelar `InterchainTokenService` to the named account without traversing `HyperionRouter`, and `AxelarAdapter::execute_with_interchain_token` fails closed (`cfg.route != RouteKind::AxelarGmp`). On `Cctp`, Circle `MessageTransmitterV2` verifies burn attestations and mints USDC before `CctpAdapter::receive` measures the balance delta and authorizes `HyperionRouter::bridge_in`.

## Authority and Timelock Separation Matrix

Router risk-widening mutations (`SetAdmin`, `SetGuardian`, `SetTreasury`, `SetFeeBps`, `SetTimelockDelay`, `SetFlowWindow`, `RegisterToken`, `EnableRoute`, `SetAdapter`, `SetRailReceiver`, `RaiseTokenFlowLimit`, `SetRouteFlowLimit`, `SetRouteConfig`, `SetRouteMaxSingleTransfer`, `Upgrade`, and EVM `SetTokenEnabled`) MUST wait out the router timelock (`MIN_TIMELOCK_DELAY = 3600` seconds to `MAX_TIMELOCK_DELAY = 2592000` seconds, expiring after `GRACE_PERIOD = 604800` seconds).

By contrast, rail adapters (`CctpAdapter`, `AxelarAdapter`, `AllbridgeAdapter` on Soroban; `CctpAdapter`, `AxelarItsAdapter` on EVM) enforce **direct immediate authority** (`require_admin` / `Ownable2Step` `onlyOwner`) with **no internal timelock queue**. In production, adapter `admin` / `owner` authority is operationally assigned to the timelocked governance multisig, and on EVM live lanes, peers, and token links are write-once so repointing requires deploying a new adapter and routing `SetAdapter` / `SetRailReceiver` through the router timelock.

Authority regimes enforced by the checker:

- `one-time-init`: Single-use contract initialization guarded by `storage::is_initialized(&env)`.
- `router-timelock`: Risk-widening router mutations gated by `timelock::queue` / `timelock::take_matured` (Soroban) or `timelockDelay` / `queued.eta` (EVM).
- `router-immediate-narrowing`: Emergency risk-reduction powers shared by `admin` and `guardian` (`pause`, `disable_route`, `disable_token`, `lower_token_flow_limit`, `cancel_action`, `pauseRoute`, `lowerTokenFlowLimit`, `cancelAction`).
- `router-immediate-recovery`: Operational pause clearance (`unpause` admin-only; `unpauseRoute` guardian or admin on EVM) that restores an already-configured route without altering adapters, fees, or limits.
- `router-blocked-bypass`: Inherited OpenZeppelin role mutators (`grantRole`, `revokeRole`) explicitly overridden to `revert Unauthorized()` so roles cannot bypass `queueAction`.
- `adapter-direct-admin`: Soroban adapter setters executing immediately upon `require_admin(&env)` (`cfg.admin.require_auth()`), distinct from router timelocks.
- `adapter-direct-owner`: EVM adapter `Ownable2Step` setters executing immediately upon `onlyOwner`, distinct from router timelocks.

## Compatibility and Migration Implications

- **Zero wire or storage changes:** Adding executable security-assumption checks does not alter Soroban XDR layouts, EVM calldata/event ABIs, token decimals, fee formulas, replay keys, or parked-claim settlement semantics.
- **Upgrade and rail activation discipline:** Promoting any `gated` rail or stack in `docs/SECURITY_ASSUMPTIONS.md` to an `active-*` posture requires an explicit external inbound evidence provider, verified contract guard, and passing regression test. Adding any new `require_admin`, `onlyOwner`, `onlyRole`, or `.bridge_in` / `.bridgeIn` surface in Soroban or EVM contracts fails CI until its authority regime and representative test assertion are recorded here.
